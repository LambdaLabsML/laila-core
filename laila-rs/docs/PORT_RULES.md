# Python → Rust port rules

The Rust port keeps the laila API *spelled the same* as the Python one.
A call that is written `laila.constant(data=[1, 2], nickname="x")` in Python is
written exactly that way in Rust, inside a `laila::python! { .. }` block.

The port is organised in three layers; each rule below names the layer it
belongs to.

| Layer | What it is | Where |
|---|---|---|
| **Tier 1** | Plain, typed Rust. `Arg` / `Args` dynamic values, `#[pysig]` argument binding, the `laila` static facade, `Result<T, LailaError>` everywhere Python can raise. | `laila-core` (`laila/src`) |
| **Tier 2** | `laila::python! { .. }` — a proc-macro that rewrites Python *expression* syntax (dict literals, keyword arguments, `in`, `is None`, slices, comprehensions, f-strings, `with`, …) into Tier 1 calls. | `laila-macros` |
| **py2rs** | `tools/py2rs/py2rs.py` — a Python-`ast` transpiler that rewrites the *statement* skeleton (`def`→`fn`, `class`→`py_class!`, indentation→braces, `try`/`except`, …) and leaves expressions verbatim for Tier 2. Deterministic: CI regenerates and diffs. | `tools/py2rs` |

Tier 2 and py2rs are the "verbatim" surface. Tier 1 is what they lower to and
what a Rust user who does not want macros can call directly.

Rules are numbered `P<n>`; `py2rs.py` cites them in comments as `[P<n>]`.

---

## Statement layer (py2rs)

### P1 — One Python file → one Rust file, one `laila::python!` block
A module becomes a file whose body is a single `laila::python! { .. }` block.
Module-level test files get `#![unittest]` inside the block (see P12).
Generated files start with
`//! Generated by py2rs from <path>. Do not edit; regenerate.` and
`#![allow(non_snake_case, non_upper_case_globals, dead_code, unused_variables, unused_imports, unused_mut, clippy::all)]`.

### P2 — Imports
* `import laila` — no-op (`use laila::prelude::*;` is always emitted).
* `import laila.x.y` / `from laila.x import Y` — `use laila::x::y;` / `use laila::x::{Y};`.
* `from . import x` / `from .m import f` — `use super::{x};` / `use super::m::{f};`.
* `import json|uuid|time|os|…` (the `PRELUDE_MODULES` set) — no-op. The
  `python!` rewriter resolves the bare name to `laila::python::stdlib::<module>`
  **unless the enclosing function binds that name** (parameter, `let`, `for`,
  `with … as`, `except … as`, `#[pysig]`). Python code frequently writes
  `uuid = str(uuid.uuid4())`; this keeps it compiling. The module statics are
  deliberately *not* in `laila::prelude` because Rust refuses a `let` whose name
  shadows a static in scope.
* `from laila.pkg import name` where the file uses `name` only as an
  attribute base (`strings._ENTRY_SCOPE`, `defaults.DefaultPool()`) imports
  a *module*: py2rs lists it in `#![modules(..)]` and the rewriter reads its
  attributes through `__getattr__` (the Rust side has a module-object static
  of the same name next to the module, e.g. `laila::macros::strings`).
* A function-level `import` is hoisted to a module-level `use` (Python binds
  a local; the comment keeps its position). `sys.path.insert(..)` at module
  level is a comment. A name that is already bound by an earlier `use`
  (the same class reached through two module paths, a hoisted import
  repeating the module-level one) becomes
  `// py2rs: `from X import Y` already imported`.
* The optional-dependency idiom at module level
  (`try: import torch; HAVE_TORCH = True except Exception: torch = None;
  HAVE_TORCH = False`) emits the branch that applies: the handler's
  statements when an imported module has no Rust twin (neither `laila`
  nor a prelude module), the body's constants otherwise.
* The runtime-probe idiom (P2c): a module-level `try` whose body does
  more than import (`_probe = FilesystemPool(); ...; HAVE_FILESYSTEMPOOL =
  True`) and whose handler sets the same flag to `False`. The flag is
  whether the body *runs*: py2rs emits `fn __laila_probe_FLAG() -> Arg`
  with the body's statements (Python syntax, lowered by the rewriter) and
  `static FLAG: LazyLock<Arg>` holding `Bool(true)` when it returned,
  `Bool(false)` when it raised. `if FLAG: register_dtype_matrix(..)`
  passes `skip_unless = FLAG` to `dtype_matrix!` (P19b), so the generated
  tests report themselves skipped, as `@unittest.skipUnless(FLAG, ..)` does.
* `from tests.functional.pools.base.compdata_roundtrip import X, ..` —
  `use laila_tests::compdata_roundtrip::{X, ..};` (`register_dtype_matrix`
  itself is the `dtype_matrix!` macro, P19b).
* Anything else — `// py2rs: import X has no Rust twin` and a note on stderr.

### P3 — `let` / `let mut`
The first assignment to a local emits `let x = …;`. If the name is assigned
again anywhere in the function (including augmented assignment, `for` targets,
tuple unpacking) the first binding is `let mut`. Later assignments are plain
`x = …;`. A local whose first value is a dynamic scalar (`None`, a literal,
a dict/list) is an `Arg`; the rewriter converts every later assignment with
`IntoArg`, which is the Rust spelling of Python rebinding. An attribute or
item assignment whose value is a local (`cache.proxy_to = origin`,
`pool[k] = e`) *shares* the local (`IntoArg::into_arg(&origin)`, a handle
clone), so the local stays usable afterwards as in Python. Parameters bound
by `#[pysig]` are `let mut` (a body may rebind them: `v = v or ..`).

### P4 — Return type
`def f(...)` → `fn f(...)`. Without a `-> T` annotation the rewriter picks
the return kind from the body: a function that never `return`s a value is
`Result<()>`, one that does is `Result<Arg>`. An annotated `-> T` becomes
`Result<T>`; a trailing expression becomes `Ok(expr)`. `return x` is kept as
`return x;` and the rewriter wraps it in `Ok(..)`.

### P5 — String literals
Python `'..'`/`".."`/`"""…"""` → Rust `".."` with escapes normalised.
`b".."` → `b".."`. `r".."` → `r".."` (raw). Triple-quoted strings keep their
newlines as `\n`.

### P6 — `//` is a comment in Rust
`a // b` → `floordiv(a, b)`. `a ** b` → `pow(a, b)`. `a @ b` → `matmul(a, b)`.
All three are prelude functions returning `Result<Arg>`.

### P7 — f-strings
`f"n={len(x)}"` → `f "n={len(x)}"` (a space after `f`: `f"` is not a Rust
literal prefix). Format specs and `!r` / `!s` conversions are passed through;
the rewriter expands the braces as Python expressions.

### P8 — Annotations
`x: int = 1` → `let x: i64 = 1;`. The map is
`int→i64, float→f64, str→String, bool→bool, bytes→Vec<u8>, list→Arg, dict→Arg, Any→Arg`.
Unknown annotations become `Arg`. Parameter annotations follow the same map;
unannotated parameters are `impl IntoArg` for module functions and `Arg`
inside `py_class!` methods.

### P9 — Rust keyword clashes
Python names that are Rust keywords (`type`, `match`, `ref`, `move`, `impl`,
`mod`, `loop`, `fn`, `struct`, `enum`, `trait`, `where`, `use`, `crate`, `super`,
`self` as a non-receiver, …) become raw identifiers: `type` → `r#type`.
Keywords shared by both languages (`in if else for while return break continue
as async await`) are read as Python by the rewriter.

### P10 — Comments
Standalone `# …` lines before a statement are emitted as `// …` at the same
indentation. Trailing `# …` on a statement line is kept as a trailing `// …`.

### P11 — Module constants
`NAME = value` at module level is evaluated once, at import time. py2rs
emits a `static NAME: LazyLock<Arg>` whose initializer calls a generated
`fn __laila_const_NAME() -> Arg { return value; }` — a function, so the
value is written in the Python expression syntax the rewriter lowers
(`static` items pass through `laila::python!` untouched). A bare read of
the name inside the block is the object: the rewriter lowers it to
`(*NAME).clone()` (laila values are handles, so the clone aliases the same
object). Module constants of the *library* (`laila.entry.transformation_base64`,
`transformation_base64_compression`) are value-returning functions in Rust;
the rewriter lowers a bare or attribute read of those names to the call
(`laila::entry::transformation_base64()`).

### P12 — `unittest.TestCase`
`class T(unittest.TestCase):` → `py_class!(T);` plus `impl T { .. }`.
With `#![unittest]` in the block, the rewriter generates one `#[test]` wrapper
per `test_*` method that runs `setUp`, the method, and `tearDown`, panicking
with the `LailaError` display text on `Err`. `self.assert*` methods are Tier 1
methods on `TestCase`; a `msg=` keyword is appended to the failure text
(`assert_with_msg`, unittest's `longMessage`). `with self.assertRaises(E)` / `pytest.raises(E, match=..)`
run their body as a `Result` closure and check the error class/text.

`@unittest.skipUnless(cond, "reason")` / `@unittest.skipIf(..)` on the
class becomes `#[skip_unless(cond, "reason")]` / `#[skip_if(..)]` on the
`impl`: every generated `#[test]` evaluates the condition (a Python
expression, usually a module flag) and reports itself skipped when it says
so, before `setUp`. Method-level `@unittest.skip*` is `#[ignore = ".."]`.

`unittest.mock.patch.object(Cls, "method", autospec=True, side_effect=..,
return_value=..)` patches a method of a laila class: the mock lives in a
process-wide registry (`laila::python::mock`) that the class's Rust
methods consult first (the `FilesystemPool` resolution / mount hooks do),
so `start()` / `stop()` / `with patch.object(..)` behave as in Python;
`MagicMock` records calls (`assert_called_once`, `reset_mock`,
`side_effect`, `return_value`). A bare class name in argument position
(`patch.object(FilesystemPool, ..)`) is the class object
(`builtins::class_value::<FilesystemPool>()`).

### P12b — `TestCase` subclasses
`class _Case(unittest.TestCase)` + `class TestX(_Case)`: `py_class!`
structs have no inheritance, so a test case deriving from another test
case of the same file carries a *copy* of every method it does not override
(`setUp`, `tearDown`, helpers), base-most first, each marked
`// py2rs: inherited from `_Case``. The base class itself is emitted too
(no `test_*` methods, so no `#[test]`s).

### P12c — Mixins and shared test names
A base-less class that other classes of the file derive from
(`class _CloseRaceMixin:` + `class TestX(_CloseRaceMixin, unittest.TestCase)`)
is a mixin: its methods are copied into the test cases as in P12b, and, as
unittest collects nothing from it, its own `test_*` methods are left out
(`// py2rs: `test_x` runs on the test cases deriving from this mixin`).
A test method that several classes of one block then define gets a
class-qualified `#[test]` wrapper, `TestX__test_x` -- pytest's
`TestX::test_x`; a name defined once keeps the bare `test_x`.

### P12d — `super()` in test cases
A test case that overrides a method of its (in-file) base *and* reaches
the base's version through `super().m(..)` carries that version too,
under the class-qualified name `<Base>__m` (the shape of Python's
private-name mangling), marked `// py2rs: `_Case.setUp`, reached through
`super().setUp()``; the call lowers to `self._Case__setUp(..)`. The copy
resolves its own `super()` calls from *its* class, so chains of
`setUp` overrides nest correctly. `super()` outside a test case (a
`py_class!` subclass of a model class) stays unsupported.

### P13 — Classes
`class C:` / `class C(object):` → `py_class!(C);` — a dynamic struct with a
`__dict__`, `__getattr__` / `__setattr__`. `class C(Base):` → `py_class!(C: Base)`
and `impl Base for C`. `self.x = v` lowers to `__setattr__`, `self.x` to
`__getattr__`. `@staticmethod` / `@classmethod` drop `&self`.

### P14 — Class attributes
`class C: x = 1` → `fn x() -> Arg { 1 }` inside the `impl` (same reason as P11).

### P14b — Pydantic models
A class (other than a `TestCase`) with *annotated* class attributes is a
pydantic model: `class C(Base): host: str = Field(default="x")` →
```
py_model! { C(Base) { host: str = Field(default="x"), } }
```
Members keep their Python spelling (`name: annotation = value`; a plain
`name = value` is a class variable). The rewriter lowers each value with the
expression rules and emits the class as a unit struct `C` (the class as a
value: `_eligible_model_fields(C)`), `C::__class__()` (the
`_compat::pydantic::ModelClass` descriptor: fields, private attributes,
class variables, bases), `C::new(args)` (`C(**kwargs)`, an `Arg` instance
whose attributes are dynamic: `c.host` → `c.__getattr__("host")`) and
`C.model_fields` → `C::model_fields()`. Base classes are the laila unit
structs (`_LAILA_IDENTIFIABLE_OBJECT`, `_LAILA_CLI_CAPABLE_CLASS`, ...),
whose hooks run in MRO order at construction. A class defined inside a
function is emitted in place (Rust items may live in bodies).

### P15 — Signatures with defaults / `*args` / `**kwargs` / keyword-only
A `def` that has any of these gets `#[pysig("f(a, b=1, *, c=None, **kw)")]`
and a single `args: impl Into<Args>` parameter. The attribute binds the names
as locals with CPython's exact `TypeError` messages
(`f() missing 1 required positional argument: 'a'`,
`f() got an unexpected keyword argument 'z'`, …). Plain positional-only
signatures stay typed Rust parameters.

### P16 — `try` / `except` / `finally`
```
try { .. } except ValueError as e { .. } except (KeyError, TypeError) { .. } else { .. } finally { .. }
```
The rewriter runs the `try` body as a `Result` closure and matches
`LailaError::class()` against the listed exception classes (subclass-aware:
`except Exception` catches `ValueError`). `raise` inside `except` without an
argument re-raises the bound error.

`return` inside the body, a handler or `else` (P16c): the closures then
yield `Option<value>` -- `Ok(Some(v))` for a `return v` converted the way
the enclosing function (`-> Arg`: `into_arg`; no return type: `()`; a
nested `def`: `into_arg`) converts its result, `Ok(None)` for falling
through -- and after `finally` ran the statement returns the carried value
from the enclosing function. A function with a typed return (`-> T`) does
not support it; move the `return` after the statement.

Python's `try` opens no scope: a name first bound inside the body or a
handler and read outside it (in `finally`, or later in the function:
`pool2 = FilesystemPool()` ... `finally: pool2.close()`) is declared
before the statement as `let mut name = None;` and assigned inside it
(the rewriter's dynamic-local rule converts the later assignment).

### P16a — Nested `def`
A `def` inside a function body is emitted as a nested `fn` (verbatim) and
the rewriter lowers it to a closure over the enclosing locals, parameters
and return value as `Arg`s. If the name is used as a *value* in the
enclosing body (`Thread(target=worker)`, `run_atomic(f)`) it becomes a
`'static` Python callable and every captured local is cloned first (laila
values are handles, so the clone aliases the same object); a def that is
only ever called directly borrows the enclosing scope (and `self`). Nested
defs with defaults / `*args` / `**kwargs` are not supported.

A nested def that escapes and reads `self` (`def writer(i):
self.pool[str(i)] = i` handed to `Thread(target=writer)`) owns a clone of
the `py_class!` handle: the body's `self` tokens are renamed to that clone.

### P16a2 — Identity of `py_class!` mixin subclasses
`class C(_LAILA_LOCALLY_ATOMIC_IDENTIFIABLE_OBJECT)` /
`(_LAILA_GLOBALLY_ATOMIC_IDENTIFIABLE_OBJECT)` → `impl Mixin for C {}` plus
`laila::dict_identity!(C);`, emitted by `laila::python!` next to the impl:
the identity the Python base class keeps in `__pydantic_private__`
(`_uuid` minted on first use, `_scopes = ["OBJECT"]`, `_evolution = None`)
lives in the instance `__dict__` (`atomic::definitions::dict_identity`).
Typed objects implement `HasIdentity` from their `Identity` (`Entry`);
pydantic model instances from their private attributes.

### P16b — Class attributes and the global-lock gate
A class attribute (`class C: x = 1`, or `n: int = 0` on a subclass of a
`laila.atomic` mixin trait, which stays a `py_class!`) is emitted like P14
with a `#[class_attr]` marker: `self.n` reads the instance attribute first
and the class default second, and the marker tells the rewriter the function
is a *value*, not a Python callable. When a class implements
`_LAILA_GLOBALLY_ATOMIC_IDENTIFIABLE_OBJECT`, the rewriter installs the
secret gate that Python installs from `__getattribute__`: every public
method is wrapped so `secret=` is stripped and verified through
`__gate__(name, args)` while the global lock is held.

### P17 — Directory mode
`py2rs tests/functional -o laila-rs/tests/functional` writes one `.rs` per
`.py` and one `main.rs` per Python package directory, declaring each module
as `#[rustfmt::skip] mod <name>;` so `cargo fmt` never touches generated
code and `py2rs --check` stays byte-exact. The `laila-tests` crate lists each
`main.rs` as a `[[test]]` target named after the directory
(`functional_entry_unit_tests`).

### P18 — Overrides sidecar
`laila-rs/tests/overrides/<source rel path>.yaml` can carry
`skip: <reason>` (do not transpile), `skip_tests: [name, …]` (drop these methods;
each leaves a `// py2rs: … skipped (override: <skip_tests_reason>)` comment),
`skip_imports: [module, …]` (an `import` whose Rust twin does not exist yet
becomes a comment), `skip_functions` (module-level defs, same shape as
`skip_tests`), `use: [path, …]` (extra `use` lines) and `builder_tokens:`
(P31). `skip_tests` and `skip_functions` also take a mapping form with a
one-line reason per name (`skip_tests:` then indented `test_name: reason`
lines). Overrides are the only manual input; the generated file is never
edited.

### P19 — Dynamic test registration
The laila suites register generated tests with
`def _case(name, fn): setattr(TestX, name, fn)` + `_case("test_001_x", _t001)`
and module-level `def _t001(self): …`. py2rs folds each registered def into
the class as a method named after the registration string, in registration
order, so the Rust test names match pytest's. The helper, the module-level
defs and the registration calls themselves have no Rust twin.

### P19b — dtype-matrix registration
`register_dtype_matrix(Cls, make_pool, store_as_json_string=..)` at module
level (bare, assigned, or under `if HAVE_X:`) attaches the numpy / torch
round-trip matrix of `tests/functional/pools/base/compdata_roundtrip.py`
to *Cls*. The helper's Rust twin is the hand-written
`laila_tests::compdata_roundtrip` (the Rust `conftest.py`, next to
`builders.rs`); py2rs emits
`laila_tests::dtype_matrix!(Cls, make_pool, store_as_json_string = .., include_torch = ..);`
which expands to one `#[test]` per matrix method with pytest's names
(`test_pool_np_int8_raw_b64`, `test_pool_np_edge_fortran_order`, …). The
torch half is empty (the port has no torch runtime, as a Python
environment without torch) and the three numpy edges without a Rust
twin (`structured_dtype`, `subarray_dtype`, `datetime64`) are not
generated. A backend suite (`test_<backend>_compdata_roundtrip.py`) needs
no override: its `make_pool` is its own module function. When the
registration is guarded by a runtime-probe flag (P2c) the macro gets
`skip_unless = FLAG` and each test skips when the backend is unavailable
(`FilesystemPool` without loop-mount privileges).

### P19d — Loops over classes
`for cls in (AtomicInt, AtomicDict, ..): …` inside a method iterates
*class objects*, which the Rust twin has no values for. py2rs unrolls the
loop into one `{ … }` block per class with `cls` replaced by the class
and `cls.__name__` by its name as a string literal. Only a tuple / list
of imported capitalised names qualifies; any other iterable stays a
runtime `for`.

### P31 — Constitution source strings are builder tokens
Rust cannot `exec` Python. A complex constitution's `code` is a *builder
token*: the same string on both sides, resolved through
`laila::entry::constitution::register_builder_token(token, builder)`
(`_exec_one_fn`), so `as_dict()` / `_hmac` stay byte-identical. A test file
whose module constant holds Python source
(`_CONSTITUTION_SRC = "def combine(manifest): ..."`) maps it to a native
twin in its override:

```
builder_tokens:
  _CONSTITUTION_SRC: laila_tests::builders::combine
```

py2rs then registers the builder under the constant's exact text inside the
constant's `LazyLock` initializer, i.e. the first time the test reads the
name (before any `Entry.variable(constitution=_CONSTITUTION_SRC, ..)`). The
twins live in the hand-written `laila-tests` library (`tests/builders.rs`,
the Rust `conftest.py`): `fn combine(manifest: &Arg) -> Result<Arg>` reads
`manifest.realized` exactly as the Python body does.

#### P31b — Inline constitution source
Source written inline in a test body
(`Entry.variable(constitution="def build(m):\n    ...", manifest=m)`) is
keyed by the literal itself in the override:

```
builder_tokens:
  "def build(m):\n    return m.realized['a'].data * 2\n": laila_tests::builders::realized_a_times_two
```

py2rs emits the literal through
`laila::entry::constitution::builder_token(<literal>, <fn>)`, which
registers the twin under the exact text and yields the text, so the Rust
test still shows the Python source and the serialized `code` / `_hmac`
stay byte-identical.

### P32 — Child-interpreter scripts are child-process functions
`subprocess.run([sys.executable, "-c", SRC.format(path=p)])` runs Python
source in a child interpreter. Rust cannot, so a module constant holding
such source maps to a Rust function in its override:

```
child_scripts:
  _HARD_KILL_CHILD: laila_tests::children::hard_kill_child
```

The constant becomes a `laila::python::stdlib::ChildScript` (a `str`-like
value: `str(SRC)` is the template text, `SRC.format(**kw)` binds the
keyword arguments), and py2rs appends a child entry after the block:

```
#[test]
fn __laila_child__HARD_KILL_CHILD() {
    laila::python::stdlib::subprocess::child_main("_HARD_KILL_CHILD", laila_tests::children::hard_kill_child);
}
```

`subprocess.run` recognises `[sys.executable, "-c", <ChildScript>]` and
re-executes the current test binary on that entry (`--nocapture`) with the
bound arguments in `LAILA_CHILD_SCRIPT` / `LAILA_CHILD_KWARGS`; outside such
a run the entry is a no-op test. `child_main` calls the function with the
arguments as `Args` and exits with its status, so the child's
`sys.stdout.write(..)`, `os._exit(0)` and crashes reach the parent's
`CompletedProcess` (`returncode`, `stdout`, `stderr`) as in Python. The
functions live in the hand-written `laila-tests` library
(`tests/children.rs`, next to `builders.rs`), each the Python template's
body in `laila::python!`.

### P33 — Scripts are programs (`--script`)
A Python file that *does* something at import time -- an example, a
tutorial cell, a benchmark -- is a program, not a module. `py2rs --script`
keeps the module's `def`s / `class`es as block items and collects the
top-level statements, in order (an `if __name__ == "__main__":` body
inlined where it stands), into one `fn main()`; the rewriter gives `main`
the `Result<()>` return so a `?` propagates like an uncaught exception
(non-zero exit, the error printed). A `def` written *after* a program
statement that reads a name the statement bound (`entries = [...]` then
`async def gather(): ... entries ...`) closes over a module global in
Python; it becomes a nested `fn` inside `main`, closing over the local.
`examples/<name>.py` → `examples/<name>.rs`, each an `[[example]]` of
`laila-core` (`cargo run --example <name>`), regenerated and diffed in CI
like the test suites, and run there end to end.

## Expression layer (`laila::python!`)

### P20 — Calls and keyword arguments
`f(a, k=v)` → `f(args!(a, k = v))` when `f` is a `#[pysig]` function or a
method of the `laila` facade; `f(a, k=v)?` otherwise. Every call that can
raise gets `?` inserted (the block body is a `Result`). User-defined Python
functions and methods receive owned `Arg`s (`IntoArg::into_arg` on each
positional).

### P21 — Constructors and module paths
`laila.Entry(..)` → `laila::Entry::new(..)`; `HDF5Pool(nickname="x")` →
`HDF5Pool::new(args!(nickname = "x"))`. `laila.entry.transformation_base64`
as a *value* → `callable(laila::entry::transformation_base64)`.
`EntryState.READY` → `EntryState::READY`.

### P22 — Attributes
`e.data` → `e.data()` when the receiver is a typed laila object with that
accessor, otherwise `e.__getattr__("data")?`. A snake_case attribute of a
*class path* is an associated function call (`Cls.model_fields` →
`Cls::model_fields()`); `Enum.VARIANT` stays a path. `uuid.UUID` and the
other stdlib classes are types in `laila::python::stdlib`. `self.x` inside `py_class!`
is always dynamic. Assignment `e.x = v` → `e.__setattr__("x", v)?`.
An attribute whose name is also a Python container *method* (`pool.index`
vs `list.index(x)`, `keys`, `items`, `get`, `pop`, `count`, `copy`, …;
`CONTAINER_METHOD_ATTRS`) cannot be a zero-argument method on `Arg`, so
it is read through `__getattr__` on every receiver. Dynamic values reach
the pool / index / router / `MultiBuffer` / `Record` attributes and methods
through the `arg_attrs!` / `arg_methods*!` forwarders on `Arg`
(`object.rs`); a new public attribute of a laila type is added there.

### P23 — Literals
`{"a": 1}` → `py!({"a": 1})` (an `Arg::Dict`, insertion-ordered).
`[1, 2]` → `Arg::List`. `(1, 2)` → `Arg::Tuple`. `None` → `Arg::None`.
`True`/`False` → `bool`. `b"…"` → `Arg::Bytes`. `{1, 2}` → `Arg::Set`
(via `builtins::set`; set comprehensions likewise).

### P24 — Operators
`+ - * / % ** //` on `Arg` follow Python: `"ab" * 2 == "abab"`, `"k%d" % i`,
`[1] + [2] == [1, 2]`, `7 / 2 == 3.5`, `-3 % 5 == 2`. Comparisons use
Python equality (`1 == 1.0`, `True == 1`); an ordering between mixed types
is `False` through the bare operator (`PartialOrd` has no exception channel)
and raises `TypeError` in `sorted` / `min` / `max`. A literal-vs-literal
expression (`1 == 1.0`) is plain Rust and stays typed; py2rs expands a
chained comparison `a < b < c` to `a < b and b < c`. `and`/`or`/`not` use Python truthiness; `and`/`or`
short-circuit and return the operand as an `Arg` (`x or default`;
conditions apply truthiness to the result). `a if c else b` yields an `Arg`
from either branch. `obj.x += v` and `d[k] += v` read and write through the
attribute / item protocol. `del obj.name` → `obj.__delattr__("name")`.
`Cls[T](..)` (a subscripted generic class) is `Cls::new(..)`. `k, v = pair`
unpacks any Python sequence (`unpack2` / `unpack3`, CPython's `ValueError`
texts). A local used as an arithmetic operand or inside a container literal
is cloned, not moved (Python shares the object). `a in b` / `a not in b` →
`b.__contains__(a)`.
`x is None` / `x is not None` → `x.is_none()`. Chained comparisons
`a < b < c` are expanded. `cache << origin` / `origin >> cache` on pools
lower to the fallible `__lshift__` / `__rshift__` (a proxy cycle is a
`ValueError`); each returns its right operand so chains nest
(`laila.alpha_pool << hdf5 << s3;`). The typed `Shl` / `Shr` operators of
`Pool` and the handles stay for Tier 1 and panic on a cycle. A shift with
an integer-literal operand (`8 << 20`, `sizes[0] * 3 + (16 << 20)`) is the
arithmetic shift and stays plain Rust.

### P25 — Indexing and slices
`d["k"]` → `d.__getitem__("k")?` (`KeyError` / `IndexError` texts match
CPython). `xs[-1]` is negative indexing. `xs[1:]`, `xs[::2]`, `s[1:-1]` →
`slice(..)`. Assignment `d["k"] = v` → `__setitem__`. `del d["k"]` →
`__delitem__`.

### P26 — Comprehensions, lambdas, ternaries
`[f(x) for x in xs if p(x)]` → a block building `Arg::List`; dict and set
comprehensions likewise; generator expressions become lists. `lambda x: x + 1`
→ a closure wrapped as `callable(..)`. `a if c else b` → `if truthy(c) { a } else { b }`.

### P27 — `with`
`with open(p) as f:` / `with laila.something() as x:` → the context manager's
`__enter__` / `__exit__` run around the block; `__exit__` runs on early `?`
too. The body is emitted *inline* in the enclosing block (Python's `with`
opens no scope: names first bound inside stay visible after it); the guard
`__enter__` returned is dropped right after the last body statement. `with pytest.raises(..)` / `with self.assertRaises(..)` are special-cased
(see P12).

### P28 — Builtins
Builtins are prelude functions with CPython semantics on `Arg`. Phase 0
ships `print len str repr int float list dict range sorted all any isinstance
hasattr truthy pow floordiv truediv getattr dir hash type callable` (the
Python `callable(x)` predicate is `builtins::is_callable`; `type(x)` returns
a `PyClass` object and `isinstance(x, type)` tests for one; `dict`, `list`,
`str`, ... used as *values* -- `default_factory=dict` -- are class objects
from `builtins::builtin_class`). The rewriter already reserves the full
builtin name set (`bool tuple set enumerate zip reversed min max sum abs
getattr setattr divmod open input exit …`) so adding one is a Tier 1 function,
never a macro change. `print` takes `Args` (`print("a", x, sep="")`).
`isinstance(x, (int, str))` accepts the type names
`int str float bool list dict tuple bytes` and any `py_class!`.
`issubclass(A, B)` takes two laila / `py_model!` classes (unit structs
implementing `ModelBase`) and walks `A`'s MRO. `bytes(x)` is
`builtins::bytes_` (`bytes` the name is the `isinstance` marker).
`NotImplemented` is a shared singleton (`builtins::NotImplemented`;
`x is NotImplemented` holds through `PyObject::__is__`). `keys(as_generator=True)`
and other Python generators are `builtins::Generator` objects over a
snapshot: iterable, not a `list`, with a no-op `close()`.

### P29 — Methods on `Arg`
Python's list/dict/str methods are inherent methods on `Arg`:
`append extend insert pop remove clear index count reverse sort copy deepcopy
get keys values items update setdefault startswith endswith upper lower strip
split join replace encode decode format`. Each returns `Result` and raises the
CPython error (`pop from empty list`, `'x' is not in list`, …).
`template.format(*args, **kwargs)` and `template % values` run at run time
with the format-spec mini-language (`{name!r:>8}`, `%(key)05.2f`;
`python::strfmt`); f-strings stay a compile-time lowering.

### P30 — Stdlib
`uuid.uuid4()`, `json.dumps(x)`, `json.loads(s)`, `time.time()`,
`time.sleep(s)`, `time.monotonic()`, `time.perf_counter()` and `pytest.raises`
live in `laila::python::stdlib` and are reached by bare module name (P2).
Modules not yet ported fail to compile at the use site with an
unresolved-path error — that is the signal to add them.

## Tier 1 contracts the layers above rely on

* Every fallible API returns `Result<T, LailaError>`. `LailaError` carries a
  Python exception class name (`ValueError`, `TypeError`, `KeyError`,
  `RuntimeError`, …) and the CPython message text. `str(err)` in Rust equals
  `str(err)` in Python.
* `Arg` is `Clone` and cheap: containers are `Arc`-backed; `copy()` /
  `deepcopy()` are explicit, as in Python.
* `laila` is a `static` facade with value proxies (`laila.memory`,
  `laila.alpha_pool`) so `laila.memory.extend(..)` needs no `&`.
* Python classes that are pydantic models (pools, the router,
  `MultiBuffer`, `Record`) are a *class* unit struct (`ModelBase`,
  `isinstance`, `::new(args)`, `laila.DefaultPool is _LAILA_IDENTIFIABLE_POOL`)
  plus an instance *handle* (`Pool`, `PoolRouter`, `MultiBufferHandle`; a
  `Record` instance is a `ModelInstance` `Arg`). A pool backend implements
  `data::PoolBackend` (the Python storage hooks, every default being the
  base-class body) and is constructed through `Pool::construct` after its
  `ModelClass` (`data::schema::base::pool_class`); see `data/s3/mod.rs` (the
  smallest) and `data/sqlite/sqlite.rs` (a persistent backend).
* `#[pysig]` binds exactly as CPython: positional, defaults, `*args`,
  keyword-only after `*`, `**kwargs`, with CPython's error messages.
* No `unsafe`, no `std` in `laila-core` beyond the `std` feature; the
  `no_std` core builds with `alloc` only
  (`cargo build -p laila-core --no-default-features --target thumbv7em-none-eabihf`).
  Locks are `parking_lot` on `std` and `spin` otherwise
  (`python::sync`); dict hashing is `RandomState` on `std` and FNV-1a
  otherwise (`_compat::hash`); float rounding goes through `_compat::fmath`
  (`libm` on `no_std`).

## Cost of the dynamic surface (Phase 0 measurement)

`/tmp`-style micro-benchmark, release build, 1 M iterations, AWS Graviton:

| Call | ns / call |
|---|---|
| typed fn with four `Arg` parameters | 74 |
| same fn through `args!(i, nickname="bench")` + `#[pysig]` | 355 |
| full `laila.constant(data=i, nickname="bench")` via `python!` | 3 446 |

Binding overhead is ≈ 280 ns per call: one `Vec` for positionals, one
`Vec<(String, Arg)>` for keywords, the `String` for `"bench"`, and the
keyword name match. `laila.constant()` is dominated by the UUID‑5 (SHA‑1) of
the nickname and the `Arc` allocation of the entry, not by binding. The typed
Tier 1 path is always available when the overhead matters.
